## Reproduction

Launch each revision from its own checkout:

```sh
npm ci --ignore-scripts
node .agents/skills/verify-openhands/scripts/control-openhands.mjs launch --new --build auto --run-id <run-id> --timeout 180
node .agents/skills/verify-openhands/scripts/control-openhands.mjs doctor --run <run-dir>
```

1. Settings → LLM: create a deepseek connection named `QA_refresh_original` with a dummy key.
2. Open Bulk add from the connection row; uncheck Select all, choose No connection (keyless), check deepseek-chat.
3. In another app tab/window open the top-level Add from provider connections chooser, choose deepseek, keyless and deepseek-chat.
4. Repeat those two arrangements at 390×844; desktop is 1440×1000.
5. In a fifth app tab/window rename the connection to `QA_refresh_RENAMED` through the UI.
6. Disconnect the browser network, wait more than 5 minutes for the query cache to become stale, then reconnect. Observe successful real `GET /api/llm/provider-connections` requests and updated labels.
7. Inspect each already-open modal. On the fix, submit the desktop row-entry modal, reload the page, read the saved profile, and reopen both entry points.

The CLI needed a local `browser offline on|off` extension using Playwright `context.setOffline`, documented in its help. It changes actual browser connectivity, without intercepting requests or editing query state. `extend-proof-harness.py` and the driving scripts are included to show the exact extension and actions. This extension is confined to verification checkouts and is not part of the product PR. CLI syntax checks and its 61 existing Vitest checks passed.

Initial focus-only attempts did not issue a refresh request in this virtual-display environment and were discarded. The evidence here uses the network-recovery trigger, not an unproven focus trigger.
